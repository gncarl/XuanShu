> 本版本三项需求已全部实现并随 v0.2.4 发布，详细变更见 `CHANGELOG.md` 的 `[0.2.4]` 章节。

- ✅ **模型属性小标签**：拉模型列表与模型池表格展示能力 chip（文本/工具/视觉/推理/文生图/视频/音频/免费）+ 上下文大小（`128K 上下文`）。三路合并：本地能力注册表（`modelMeta.js`）+ 上游扩展字段（`context_length` 等）+ 命名推断兜底（标「推测」）；模型池每行「属性」按钮可手动修正并持久化（用户修正优先，导入导出保留）。

## 0.2.5（规划中 · 2026-10-16 记录）

- [ ] **拉模型弹窗支持「取消勾选 = 取消加入」**：当前「拉取模型」对话框只能正向加入，无法反向操作。需求：对**已经加入模型池的模型**，在列表中以已勾选状态呈现；用户**取消勾选即从模型池移除**（取消加入）。即在同一弹窗内完成「加入 / 取消加入」双向操作，不必再切到模型池表格逐个删除。
  - 涉及：`src/pages.tsx` 拉模型弹窗（搜索框 + 复选框列表 + 底部「加入的分组 / 加入后的优先级」）；需要把「已在模型池中的模型」与「本次新拉取」合并进同一列表并回显勾选态；取消勾选时调用删除模型接口。
- [ ] **频道停用后其名下模型同步从模型池隐藏 / 移除**：在频道管理里关闭某频道时，该频道已加入模型池的模型应同步在模型池中**不再显示**（或直接移出模型池），避免「频道已关但模型池仍挂着必失败的模型」。
  - 说明：路由层（`router.js:_availablePool()`）已过滤 `!ch.enabled`，**不会**造成 failover 失败；此项主要解决模型池 UI 展示与语义一致性。
  - 待定策略（实现前确认）：**隐藏但保留**（频道重新启用后模型自动回归）vs **真删除**。倾向前者（隐藏/置灰），避免误删用户已配置的模型与属性修正。

## 0.2.6（规划中 · 2026-10-17 记录 · 路由提速）

> 来源：《docs/routing-research-2026-10.md》调研结论。目标：缩小与 LiteLLM/OpenRouter 在连接管理与延迟反馈上的差距。P0 三项优先。

- [ ] **P0-1 HTTP keep-alive 连接复用 + DNS 缓存**：`proxy.js` `_forwardOnce` 目前每次请求裸建 TCP/TLS（国内→海外单次握手约 300–600ms）。按 channel 维度建 `https.Agent({keepAlive:true})` 池 + DNS 查找缓存（TTL 60s）。改动集中在 proxy.js，不动数据模型。
- [ ] **P0-2 latency-based 路由（EWMA）**：按 `(channelId, upstreamModel)` 维护 EWMA 延迟（`new = 0.3×当前 + 0.7×历史`），作为 AUTO/路由策略排序中 priority 之后的次级排序键；设 `lowest_latency_buffer`（默认 0.5）防最快单点吸流；重试成功即衰减。建议设置里加 `latencyFirst` 开关。
- [ ] **P0-3 429 尊重 `Retry-After`**：`_forwardOnce` 解析 429 响应头（秒或 HTTP 日期），冷却该候选至指定时刻，替代固定 `cooldownMs`。
- [ ] **P1-1 least-busy 并发均衡**：router 维护每候选 in-flight 计数，priority 相同或 roundrobin 组内优先选空闲候选。
- [ ] **P1-2 TTFT 单独打点**：流式首字节到达时记 `ttftMs`，路由用 TTFT 的 EWMA；仪表盘展示。
- [ ] **P1-3 后台预热探测**：定时任务（如 5 分钟）对启用候选发 1-token 请求，预热连接 + 刷新 EWMA。
- [ ] **P2-1 动态 priority 微调**：按近期成功率对静态 priority ±1 档浮动。
- [ ] **P2-2 并行 hedging**：首候选超过 P75 延迟无首字节时并行试探第二候选；有双写风险，建议仅非流式开启，默认关。
