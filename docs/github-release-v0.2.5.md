# 玄枢 XuanShu v0.2.5 · GitHub 发布说明

> 本版本完成 0.2.5 全部待办：拉模型弹窗「取消勾选 = 取消加入」、频道停用后模型池同步隐藏，以及一组路由提速改造（keep-alive 连接复用、EWMA 延迟路由、429 Retry-After）。

## 本版本一句话

拉模型列表里已加入模型池的模型默认勾选，取消勾选即移出模型池；关掉某频道，它名下的模型随即从模型池隐藏（数据保留，重开即回归）；转发改用 keep-alive 连接池 + DNS 缓存，同优先级候选里实测最快的第一个被尝试，429 按上游告知的恢复时长冷却。

## Release notes 可直接粘贴

```markdown
### 新增
- **拉模型弹窗支持「取消勾选 = 取消加入」**：已加入模型池的模型在拉取列表中以勾选态回显，取消勾选即从模型池移除——同一弹窗内完成「加入 / 取消加入」双向操作，不必再去模型池表格逐个删。底部按钮按实际变更动态显示（加入选中的 N 个 / 取消加入 N 个 / 应用变更），移除前有确认；顶部摘要实时显示「共 X · 已在池 Y · 待加入 Z · 待移除 W」。
- **频道停用后其名下模型从模型池隐藏**：在频道管理关闭某频道，模型池默认不再显示其名下模型（数据保留，频道重新启用后自动回归，不会误删已配置的模型与属性修正）。模型池页新增「显示已停用频道的 N 个」开关，展开后相关行置灰并标「已停用」。
- **模型池「延迟」列**：按「频道 + 上游模型」展示实测延迟（首字 TTFT 优先，悬停看首字 / 总耗时 / 成功 / 失败次数），每 30 秒自动刷新，来自网关自身的调用统计，不是探测估值。

### 优化（路由提速）
- **keep-alive 连接复用**：转发不再每次新建 TCP/TLS 连接，按频道维度维护连接池。国内直连海外 API 单次 TLS 握手约 300–600ms，这是「感觉慢」的最大来源之一。
- **DNS 结果缓存**：转发前缓存解析结果 60 秒，减少每次请求的递归查询。
- **EWMA 延迟路由**：只统计成功请求，按指数加权平均记录每个上游的总耗时与首字延迟。设置里原有的「最快优先」排序本次真正实现（新增「最快档缓冲」防止流量全被最快的一个吸走）；「自定义优先级」模式下，同优先级候选之间实测快的排前面——多数用户候选同为 priority 100，此改动直接让最快的健康候选第一个被尝试。
- **429 限流尊重 Retry-After**：按上游响应头告知的时长冷却该候选（而不是固定 5 分钟），需要等太久时跳过原地重试、直接切换下一个候选，恢复期内不再反复撞墙。

### 测试
- 50 项自动化测试全部通过（含新增的 EWMA 排序双模式、延迟快照端点、429 Retry-After 冷却与切换、连接池与 DNS 缓存用例）。
```

## 升级注意

- 配置格式无变化，`config.json` 向后兼容，直接覆盖安装即可。
- 「最快优先」排序需要累计调用数据后生效（新模型无数据时排在后段）；日常推荐用默认的「自定义优先级」——同优先级自动按实测延迟排序，无需任何设置。
